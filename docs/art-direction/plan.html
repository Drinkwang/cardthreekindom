《拍案三国》美术迭代计划案

版本：视觉探索 v1 · 2026-10-03
适用工程：D:\Pro\cardthreekindom
本轮交付：六种风格参考、两个重点方向的资产样板、现状截图、可执行迭代计划与本地浏览页。

本轮图片是概念参考，界面布局和示例数值用于风格比较。它们不是游戏截图，也不是已经接入游戏的素材。现状截图另列于 baseline/。游戏逻辑与正式资源保持现状，后续按照下列阶段接入。

1. 产品定位与本轮目标

一句话：把三国名将印成手里的纸牌，让玩家在一张桌上拍翻、收集、养成，最后把荆州经营起来。

美术需要同时支持三种感受：拍下去有力、翻过来想收、回营后看得懂成长。第一眼必须看到桌上的敌牌，人物插画服务于纸牌辨识，养成界面服务于清楚的操作。

本方案以当前工程为依据：

  • 主桌面：单击轻拍，消耗 1 耐力；按住划过重拍，伤害 ×2.5、每张消耗 2 耐力。敌牌正面朝上并略有旋转，拍翻后收集。
  • 局内与局外：耐力耗尽结算回大本营；清桌后选荆州舆图中的下一站。
  • 大本营：三层技能树、出征、武将升级、每将独立装备与带兵。
  • 底部上阵条：主角固定，携带位初始 3、上限 6；卡池默认收起。
  • 城建：城池提供槽位，建筑提供收益；开包负责收集反馈。
  • 装备不进入敌牌桌面；每将有自己的装备槽，士兵没有装备槽。

设计底线：不引入回合结束、法力、手牌扇形区、战棋格、站立战场单位等另一类游戏的视觉语法。

3. 六种风格比较

以下为本项目适配判断与制作量估计，不是市场调研结论，也不代表玩家测试结果。

方向 视觉关键词 最适合本项目的部分 主要制作风险 角色定位
A 怀旧印刷 连环画、旧纸、网点、朱印、木课桌 全流程统一，拍卡动作与收藏体验都自然 做旧过量会脏，小字区网点影响阅读 主推方向
B 16 位像素 清楚轮廓、有限色板、硬边、跳帧 拍卡反馈、士兵批量生产、低分辨率表现 中文小字与自由旋转容易糊；必须人工统一像素网格 第二候选
C 水墨工笔 矿物色、墨线、留白、印章 名将卡、舆图、章节画 小卡中细线易消失；过多水墨会削弱打击清晰度 国风气质候选
D 木刻版画 黑白块面、刀刻线、三色套印 武将轮廓、阵营标志、强烈拍击图形 人物容易同质化，黑块不能侵入文字区 独立游戏辨识候选
E 漫画赛璐璐 强轮廓、两段阴影、夸张表情 角色记忆点、打击反馈、收集展示 人物服饰与表情需固定规范，避免不同卡像不同作品 轻快爽感候选
F 纸雕微缩 纸层、浅浮雕、手工模型、柔和投影 城建、菜单、卡包、纸牌物感 所有角色都做复杂层次成本较高；小卡容易阴影过重 空间与经营感候选

建议先把 A 与 B 各做一个可玩样板，再定最终方向。如果选择 A，可以吸收木刻的强轮廓；如果选择 B，整个项目遵守同一套像素网格。不要在同一套正式卡池内随机混用六种画法。

A 的统一规范

  • 颜色：纸白 #F1E6CA、墨黑 #2B211A、朱红 #B8482B、木色 #674530；魏 #294A80、蜀 #A52E24、吴 #21665B、群雄 #8C681C。
  • 人物：胸像或半身，面部与标志武器都有清楚轮廓；网点在插画里，正文底保持干净。
  • 桌面：深中性色，中央低对比，边缘体现使用痕迹；道具不得遮挡可点区域。
  • UI：浅纸面板、深墨字、红色主动作；按钮只做轻微印刷纹理。
  • 特效：纸屑、印章冲击、短促墨线；高星可有金墨，但不持续全屏闪光。

B 的统一规范

  • 以 640×400 的逻辑画布探索，优先对应 1280×800 的 2 倍显示；这是候选规范，需在实际窗口尺寸验证。
  • 普通角色原画目标 48×64 或 64×64 逻辑像素，图标 16×16 / 24×24，建筑 48×48 / 64×64。
  • 约 32 色基础色板，轮廓 1～2 逻辑像素，阴影 2～3 个明度阶；禁止把平滑插画简单像素化作为定稿。
  • 图像使用最近邻采样；UI 文字独立排版。若中文像素字体不够清楚，使用清楚的中文屏幕字体并保持整数坐标。
  • 当前卡牌可自由旋转：样板先比较 0°、小角度与固定角度。若旋转破坏像素整齐度，优先降低静止旋转量，用位置错落、像素投影表现散牌。
  • 非整数倍窗口采用留边或另一套布局规则，不通过随意拉伸破坏像素网格。上述设置在接入阶段实测后定稿。

4. 卡面与信息设计

卡面结构

保持现有约 1:1.38 的宽高比，先验证 92×127、106×146、160×221 三档显示尺寸。

从上到下：姓名 → 人物/建筑/物品图 → 阵营与稀有度角标 → 血条与必要数字。常驻桌牌不放长篇技能描述，详细效果通过悬停或详情页展示。

最小卡牌示意预算：上下薄框合计 8 px、姓名 18 px、插画约 54 px、阵营/星级 14 px、血条 8 px、数字 13 px，其余用于间隔。最终以中文姓名长短与实机可读性调整，不能仅凭大图定稿。

三种编码相互独立

含义 第一信号 第二信号
阵营 小旗/印章内的「魏、蜀、吴、群」 窄条阵营色
稀有度 1～6 星数 边角纹样，从素边到双角、印章、金墨
卡牌类型 人物、兵器、建筑、城池的清楚轮廓 类型图标和短标签
敌我 所在区域：桌面敌牌 / 底部友军 血条与上阵槽样式
关底 「关底」角签 更强轮廓与一次入场提示

稀有度不要占用阵营整张底色；高星不必把边框越做越厚。受伤时更新血条与短暂冲击，不让文字跟着长时间抖动。

人物识别规则

  • 关羽：长须、绿袍、青龙偃月刀；小尺寸必须保留长须与刀的轮廓。
  • 张飞：浓须、强壮颈肩、丈八蛇矛；与关羽的细长须区分。
  • 赵云：银甲、清楚的长枪、干净年轻面部；不堆叠碎小银甲纹。
  • 甘宁：头巾、铃饰、游侠感；小尺寸以头巾和轮廓区分。
  • 士卒按兵种先辨识：枪兵的直枪、弓手的弓弧、乡勇的布衣、黄巾的头巾；再用局部配件表现阵营。

这套规则是美术设定，并不改动已有卡牌 ID、名称、星级和属性。

6. 拍击与收集反馈

下列时长是首轮调试目标，需实际手感验证。

事件 动作 特效 目标时长
悬停/命中预览 轻抬牌，描边显示可拍目标 一圈低亮轮廓 80～120 ms
轻拍 牌短促压下并恢复 小纸屑、局部环、一次伤害字 100～160 ms
重拍划过 连续命中的牌依次响应 短轨迹，范围清楚，不遮挡下一张牌 单张 140～220 ms
暴击 更明显的缩放与回弹 朱印或漫画角星，数字提高对比 180～260 ms
拍翻收集 翻面 → 轻跃 → 朝收藏位置收束 卡背与少量纸屑 260～420 ms
城池解锁 节点印章盖下 路线亮起一次 300～500 ms
高星开包 翻面后停留展示 角纹/光色一次展开 700～1200 ms，可跳过

特效层不捕获鼠标；提供降低震动/闪动的选项。声音在接入阶段配合轻拍、重拍、翻纸与盖印，节奏与动作同时起止。

9. 接入约束

  1. 概念图保存在 docs/art-direction/，通过该目录的 .gdignore 与正式资源隔离。
  2. 正式资源建议另建 assets/art_v2/，按卡牌 ID 命名，先接 10 张样板。背景与插画是栅格，姓名、星级、血量与数值继续由 Godot 绘制。
  3. _mk_card() 增加人物图层并保留桌面统一命中；图像节点忽略鼠标。卡池、上阵条、详情与开包共用同一张肖像及裁切规则。
  4. 卡框保持透明或九宫格结构；九宫格边距必须与源图实际边框匹配，拉伸中心与边不放会变形的密集纹理。不要把整张概念图直接裁成所有控件。
  5. 像素图和非像素图分别制定导入规则；不对正式 UI 文本使用整屏像素滤镜。
  6. 当前 JSON 为上游生成的数据；本轮没有修改。后续如需新增图像索引，优先新增独立映射文件，保持原 ID；确需改数据时先找回上游生成脚本。
  7. 更新资源后先重新导入工程，再使用 tests/Screenshot.tscn 截图对比；若修改交互或养成代码，再运行现有核心自检。
  8. 原 README 的“AI 不支持透明底”是旧管线记录；新素材是否有透明通道以实际输出检验为准。参考整屏图无需透明，正式切图另行制作并检验边缘。

10. 本轮参考图与使用方式

references/ 中的六张主桌面图在尽量相同的功能构图下改变风格；另外两张展示主推与第二候选的角色、卡框、建筑、特效样板。图中混合示例角色用于视觉压力测试，不代表某关真实敌人编成；小字与数值以工程为准。

在 index.html 可按风格筛选、放大原图并查看现状截图。prompts.json 保存每张图片实际使用的完整提示词，方便复现和继续迭代。生成使用内置 imagegen 工具。

建议评审顺序：先看桌面整体 → 缩到实际屏幕尺寸 → 看小卡人物 → 看底部上阵 → 看特效 → 最后看资产样板。先选完整画面的方向，再处理单张名将精修。

建议决策：以 A 怀旧印刷为主线深化，B 像素作为完整替代方案。下一次接入从“10 张样板 + 一张桌 + 一次拍翻”开始。
